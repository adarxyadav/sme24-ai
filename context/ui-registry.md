# UI registry

Every reusable component, one line each: `ComponentName (path) — what it's for, key props/slots`. Match before inventing; update this file whenever a component is added, changed, or removed.

## Primitives (`components/ui/`)

- `Card` (components/ui/card.tsx) — shadcn card; slots `CardHeader`, `CardTitle`, `CardDescription`, `CardAction`, `CardContent`, `CardFooter`.
- `Field` (components/ui/field.tsx) — shadcn form field layout; `Field` (`orientation` vertical|horizontal|responsive), `FieldGroup`, `FieldSet`, `FieldLegend`, `FieldLabel`, `FieldContent`, `FieldTitle`, `FieldDescription`, `FieldError` (`errors[]` or children), `FieldSeparator`.
- `Input` (components/ui/input.tsx) — shadcn text input; native props, `aria-invalid` styles the error state.
- `Label` (components/ui/label.tsx) — shadcn label; used via `FieldLabel`.
- `Separator` (components/ui/separator.tsx) — shadcn separator (pulled in by Field); `orientation`.
- `Table` (components/ui/table.tsx) — shadcn table; slots `TableHeader`, `TableBody`, `TableFooter`, `TableRow`, `TableHead`, `TableCell`, `TableCaption`; scrolls horizontally inside its own wrapper.
- `Badge` (components/ui/badge.tsx) — shadcn badge; `variant` default|secondary|destructive|outline|ghost|link, `asChild`. Status/confidence colour is a semantic text class on `outline`, never a new variant.
- `Textarea` (components/ui/textarea.tsx) — shadcn textarea; native props.
- `Checkbox` (components/ui/checkbox.tsx, client) — shadcn/Radix checkbox; with `name`/`value` it submits as a form field. Used via `FieldLabel` pairs.
- `RadioGroup` (components/ui/radio-group.tsx, client) — shadcn/Radix radio group; `RadioGroup` (`name`, `defaultValue`) + `RadioGroupItem` (`value`).
- `Button` (components/ui/button.tsx) — shadcn button; `variant` default|outline|secondary|ghost|destructive|link, `size` default|xs|sm|lg|icon|icon-xs|icon-sm|icon-lg, `asChild` to render a Link. `buttonVariants` exported for link-as-button.
- `Sidebar` (components/ui/sidebar.tsx, client) — shadcn sidebar family: `SidebarProvider` (cookie-persisted state, sheet below `md`), `Sidebar` (offcanvas collapsible), `SidebarHeader`/`SidebarContent`/`SidebarFooter`, `SidebarGroup` + `SidebarGroupContent`, `SidebarMenu`/`SidebarMenuItem`/`SidebarMenuButton` (`isActive`, `asChild`), `SidebarInset` (renders `<main>`), `SidebarTrigger` (sr-only label); styled by the `sidebar-*` tokens.
- `Sheet` (components/ui/sheet.tsx, client) — shadcn/Radix sheet dialog; pulled in as the Sidebar's mobile mode. `side` top|right|bottom|left.
- `DropdownMenu` (components/ui/dropdown-menu.tsx, client) — shadcn/Radix dropdown family (`DropdownMenu`, `Trigger`, `Content`, `Item`, `Label`, `Separator`, `RadioGroup`/`RadioItem`, `CheckboxItem`, `Sub*`); drop shadows removed per the hairline-elevation rule (the `ring-1` stays). Content defaults to trigger width.
- `Avatar` (components/ui/avatar.tsx, client) — shadcn/Radix avatar (`Avatar` with `size` sm|default|lg, `AvatarImage`, `AvatarFallback`, group/badge slots); used with an initials fallback — no user images exist.
- `Skeleton` (components/ui/skeleton.tsx) — shadcn loading placeholder; pulled in with Sidebar, unused elsewhere yet.
- `Tooltip` (components/ui/tooltip.tsx, client) — shadcn/Radix tooltip (`Tooltip`, `TooltipTrigger`, `TooltipContent`, `TooltipProvider` — not self-providing); pulled in with Sidebar, used only by `SidebarMenuButton`'s `tooltip` prop (icon-collapse mode, which we don't run).

## Composites

- `LoginCard` (components/portal/LoginCard.tsx, client) — the single sign-in card: Google button, separator, magic-link email form with a Turnstile widget (token as hidden field, submit disabled until it passes); `next` (validated path forwarded to both doors), `error` (human copy rendered as an alert). Swaps itself for a "Check your email" state after a successful send (`useActionState` on `requestMagicLink`).
- `MagicLinkConfirm` (components/portal/MagicLinkConfirm.tsx, server) — "Almost there" card whose single button POSTs the token to `confirmMagicLink`; `tokenHash`, `next`. The token is spent on POST only, so a prefetched GET cannot consume it.
- `BrandMark` (components/marketing/BrandMark.tsx, server) — the SME24 logo lockup (mark + wordmark) as inline SVG with token fills (`fill-foreground`/`fill-background`), so it follows the theme; `className` for sizing; `aria-hidden` — the consumer provides the accessible name.
- `AuthNav` (components/marketing/AuthNav.tsx, async server) — header auth controls: a Log in link when signed out; "For experts"/"Expert area" link (by role), email + Log out form (calls `actions/auth#logout`) when signed in. Rendered inside `SiteHeader`.
- `HowItWorks` (components/marketing/HowItWorks.tsx, server) — "How it works": the five pipeline stages as a numbered grid; no props.
- `Features` (components/marketing/Features.tsx, server) — "What you get": five Card tiles naming the report's parts; no props.
- `PackagesSection` (components/marketing/PackagesSection.tsx, server) — "Packages": the four tiers from `lib/packages/tiers.ts` as Cards (price excl. MWST or "On request", format/scope/output/outcome), one CTA, the tier-3 scope note; `ctaHref`, `ctaLabel`.
- `ExpertsCta` (components/marketing/ExpertsCta.tsx, server) — "For experts" strip linking `/expert/apply`; no props.
- `SiteShell` (components/marketing/SiteShell.tsx) — page frame for every non-dashboard surface: SkipLink + SiteHeader + `<main id="main">` + SiteFooter; `children` fill main. Used by `app/(site)/layout.tsx`.
- `ThemeProvider` (components/marketing/ThemeProvider.tsx, client) — next-themes provider in the root layout: class-based dark mode, light default, system optional; `children`.
- `ThemeToggle` (components/marketing/ThemeToggle.tsx, client) — light / dark / system segmented control (icon Buttons with `aria-pressed`, mounted guard); rendered in `SiteFooter`; no props.
- `SiteHeader` (components/marketing/SiteHeader.tsx) — top bar inside `AutoHideHeader`: brand link (`BrandMark`, `aria-label` on the link) left, centered primary `<nav>` (How it works / Expert network / Packages anchors, hidden below `md` — the footer nav is the mobile path), `AuthNav` right; no props.
- `AutoHideHeader` (components/marketing/AutoHideHeader.tsx, client) — sticky `<header>` that hides on scroll down and reappears on scroll up (always shown near the top, revealed by keyboard focus, `motion-reduce` drops the transition); `children` fill it, so server content passes through.
- `SiteFooter` (components/marketing/SiteFooter.tsx) — copyright + tagline, a footer nav (How it works, Packages, Expert network, Log in) and the `ThemeToggle`; no props.
- `SkipLink` (components/a11y/SkipLink.tsx) — visually hidden "Skip to content" link to `#main`, visible on focus.
- `NotFoundCard` (components/marketing/NotFoundCard.tsx, server) — the one 404 body ("Page not found" + back link); shared by `app/not-found.tsx` and `app/(site)/not-found.tsx`; no props.
- `SearchForm` (components/portal/SearchForm.tsx, client) — the run intake as an ask-bar composer (T-037): one large autofocused company-name input in a hairline panel; optional website, safety-report PDF (paperclip → removable chip; uploaded first to `/api/uploads`, the returned path sent as `uploadedReportPath`), reporting period and the canonical 7 KPI fields (a quiet ledger of single-line `ValueInput` rows — period first in the same cell grammar, one muted caption per basis group instead of per-row subtitles, half-strength dividers; Enter advances rows and falls through to submit on the last; count in the header only when filled, one-sentence consequence footer, no Done — Escape/outside press/submit close; values parse tolerantly at submit via `parseLocaleNumber`, unparseable fields dropped silently) live behind `Website` / `Your figures` `DisclosureChip`s that float below the bar as viewport-fitted panels (one at a time; Escape / Done / outside press closes) — closed sections stay mounted so typed values still submit, and a filled closed section marks its chip (figures: `· N` count, website: teal dot). The panels are siblings of the bar, so the bar's focus ring reflects only its own fields — a panel holding focus leaves the bar at rest; number fields hide native spinners (they would crowd the unit suffixes). Submit is a teal pill circle (spinner while pending); errors are one alert-icon line under the composer. POSTs JSON to `/api/runs` and navigates to the returned run. Blank KPI fields are omitted from `kpis[]`, never sent as empty strings. No props.
- `DisclosureChip` (components/portal/DisclosureChip.tsx, client) — the composer's disclosure toggle: ghost pill Button with `aria-expanded`/`aria-controls`, plus icon when closed; closed-but-filled shows `· count` when `count` is passed, else a teal dot; `id`, `label`, `controls`, `expanded`, `filled`, `count?`, `onClick`.
- `ValueInput` (components/portal/ValueInput.tsx, client) — Notion-style quiet numeric value cell: the cell is the control and its weight says its state — fully ghost while empty (transparent border and fill, `bg-muted` on hover only), lifted to `card` with `border-border` + `shadow-xs` once it holds any non-whitespace text, the system focus grammar (`border-ring` + `ring-ring/50`, matching `Input`) + forced card bg on focus, `border-foreground/40` when `dirty`; right-aligned mono `tabular-nums` `text-sm`, plain text with `inputMode="decimal"` (never `type="number"`; callers may override `inputMode`), width from the caller's `className`. Controlled: standard input props plus `value: string`, `dirty?`. The file also exports `parseLocaleNumber` — the tolerant submit-time parser (apostrophe/space thousands, comma or dot decimals; null for blanks, garbage and negatives, a typed zero survives).
- `ExpertProfileForm` (components/expert/ExpertProfileForm.tsx, client) — the expert application/edit form: name, headline, bio, years, checkbox groups from `lib/experts/catalogue` (competencies, sectors, languages, regions), availability radio; `useActionState` on `actions/expert#saveExpertProfile`, refreshes on save; `expert` (row or null), `submitLabel`.
- `ExpertMatchesList` (components/expert/ExpertMatchesList.tsx, server) — the expert's client matches: company, rank, date table or "No matches yet"; `matches` (from `lib/experts/read#getOwnMatches`).
- `ExpertStatusCard` (components/expert/ExpertStatusCard.tsx, server) — fixed copy per application status; `status` (pending|approved|rejected).
- `UserMenu` (components/dashboard/UserMenu.tsx, client) — the sidebar footer's account menu (T-038): one `SidebarMenuButton` (avatar initial + truncated email + chevron) opening a `DropdownMenu` (right of the trigger on desktop, above on mobile) with the email label, the theme radio group (light/dark/system via `next-themes`; content mounts only open, so no mounted guard) and Log out (form → `actions/auth#logout`); `email`.
- `DashboardShell` (components/dashboard/DashboardShell.tsx, server) — the dashboard's own chrome (T-033), replacing `SiteShell` on `/dashboard`: `SidebarProvider` + `SkipLink`, sidebar (brand link, `DashboardNav`, "Analyses" group with `AnalysesNav`, footer with `UserMenu`), `SidebarInset` as `main#main` with a slim `SidebarTrigger` top bar and a `max-w-5xl` content column; reads the `sidebar_state` cookie so the collapse survives reloads; `email`, `role`, `runs`, `children`.
- `DashboardNav` (components/dashboard/DashboardNav.tsx, client) — the sidebar menu: New search (`/dashboard`, exact-match active), plus Expert area (`/expert`) for role expert or Admin (`/admin`) for role admin; closes the mobile sheet on click; `role`.
- `AnalysesNav` (components/dashboard/AnalysesNav.tsx, client) — the run history as sidebar items, chat-history style (T-035): company name per run (truncated, `title` for the full name) linking `/dashboard/runs/[id]`, the open run active by exact pathname, "No analyses yet." when empty; closes the mobile sheet on click; `runs` (`{id, companyName}[]`, newest first from the layout via `lib/portal/runs#listRuns`).
- `RunStatusCard` (components/dashboard/RunStatusCard.tsx, server) — a run's company name, domain, `RunStatusBadge` and one of five state blocks (queued, in progress, completed, nothing public found, delayed) keyed on `lib/portal/run-state`; `run`. The failed block is fixed copy — it reads nothing but the status.
- `RunProgress` (components/dashboard/RunProgress.tsx, client) — polls the run page while a run is queued or in progress: `router.refresh()` every 5 s re-renders the Server Component through the read layer; renders a one-line "updates automatically" note. Mounted by the run page only for live states; no props.
- `RunStatusBadge` (components/dashboard/RunStatusBadge.tsx, server) — the run state's label as an outline Badge with its token; `status`. Used by `RunStatusCard` and the admin run table.
- `FindingsStrip` (components/dashboard/FindingsStrip.tsx, server) — the report's signature (T-039): the whole report as one masthead strip — five entries in pipeline order, uppercase label over a mono figure, each an anchor to its section; an entry with nothing to say renders muted (`dim`) instead of dressing an absence as a number; staggered rise-in under `motion-safe`; `findings` (`{href, label, value, dim?}[]`).
- `ChapterRule` (components/dashboard/ChapterRule.tsx, server) — the report's numbered chapter rule (mono number, title, hairline to the right edge) — numbered because the pipeline is a real sequence; `n`, `title`.
- `IncidentCostCard` (components/dashboard/IncidentCostCard.tsx, server) — chapter 3, the invoice pass (T-039): eyebrow header, mono CHF-range hero + claim, the cost rail (severity segments of the max total — destructive/warning/input tokens, the lost-time min–max spread hatched), severity line items (dot, `count × rate` math with ≈ for derived counts, amount; zero rows muted with an outline dot), footer notes (derived counts with formulas, lost-time unknown, unpriced counts, per-incident rates); null `cost` renders the muted "Cannot be estimated" variant with a new-search link; `cost` (from `lib/portal/incident-cost#buildIncidentCost`). Completed runs only.
- `BenchmarkCard` (components/dashboard/BenchmarkCard.tsx, server) — chapter 2 (T-039): eyebrow + maturity pill header, "Rank n of N on TRIR" hero (or no-comparable / insufficient copy — insufficient renders the empty variant), the rank strip (every comparable rate as a position dot on one hairline axis, the company the only filled-teal mark, from `Benchmark.comparable_rates`), verdict + rationale panel, references `dl`, peer table with per-peer basis and "not ranked" marks, provenance footer; `benchmark` (from `lib/portal/benchmark#getRunBenchmark`). Completed runs with a row only.
- `ExpertMatchesCard` (components/dashboard/ExpertMatchesCard.tsx, server) — chapter 4 (T-039): eyebrow + "Who can help" hero, ranked expert rows — fit block (`#n · fit`, mono score / 100, teal fit bar; the score is shown per the report brief, superseding the earlier score-hidden ruling), name/headline/rationale/competency badges/facts, availability as a toned dot (success/warning; unavailable = muted outline) — or the "No expert matched yet" empty variant; `matches` (from `lib/portal/matches#getRunMatches`, labels pre-resolved, availability as `{key, label}`).
- `ProposalCard` (components/dashboard/ProposalCard.tsx, server) — chapter 5 (T-039): eyebrow header with "Download PDF" (60 s signed URL) — the report's single filled-teal action — title + executive-summary hero, recommended package panel (tier, price excl. MWST, format · output, rationale), key risks, EHS Vault sources or the "drafted without reference material" note; `proposal` (from `lib/portal/proposal#getRunProposal`).
- `KpiLedger` (components/dashboard/KpiLedger.tsx, server) — chapter 1 as one card (T-039): header with title, the shared period (when all valued rows agree) and the seven-tick disclosure meter (`filled/7`, ticks in contract order, teal when a stored value exists); the provenance table — metric + hint, mono value + unit (or ≈ derived value + formula line per design.md Derived figures, or Not disclosed), period, confidence as a toned dot (`derived` outline Badge for derived rows), source link + single-line excerpt, "Uploaded report", "Client-provided", or "Derived from <inputs>"; empty rows muted throughout; consequence footer. Below `md` each row stacks into the two-line mobile grammar (period hidden). `rows` (from `lib/portal/ledger#buildLedger`).

- `AdminNav` (components/admin/AdminNav.tsx, server) — section links for the admin surface (Overview, Runs, Users, Experts); no props.
- `AdminRunTable` (components/admin/AdminRunTable.tsx, server) — every run with owner email, `RunStatusBadge`, tier, started; `runs`, `emails` (Map user id → email).
- `AgentLogTable` (components/admin/AgentLogTable.tsx, server) — a run's `agent_logs` in order: time, stage, level badge, message, raw payload; `logs`.
- `ExpertDecisionForm` (components/admin/ExpertDecisionForm.tsx, client) — Approve / Reject buttons for one application (`useActionState` on `actions/admin#setExpertStatus`), or the settled status; `userId`, `status`.

## Pages of note

- Chrome split (T-033): `app/(site)/layout.tsx` wraps the marketing, auth, expert, admin and design routes in `SiteShell`; the root layout carries only fonts + `ThemeProvider`; `/dashboard` renders in `DashboardShell` instead.
- `/login` (app/(site)/(auth)/login/) — `LoginCard`, centered by `app/(site)/(auth)/layout.tsx`; reads `next` and `error` from the query string.
- `/auth/confirm` (app/(site)/(auth)/auth/confirm/) — `MagicLinkConfirm`, same centered layout; noindex. Missing token → `/login?error=link_expired`.
- `/` (app/(site)/page.tsx) — the marketing page: hero with one CTA (signed in → `/dashboard`, signed out → the login door with `next=/dashboard`; no `SearchForm`, T-034), then `HowItWorks`, `Features`, `PackagesSection`, `ExpertsCta`; own metadata title + description.
- `/dashboard` (app/dashboard/page.tsx) — the dashboard default: centered greeting + `SearchForm` composer (T-037); `app/dashboard/layout.tsx` reads `getUser` and mounts `DashboardShell`, `app/dashboard/not-found.tsx` is the not-found state in app chrome. noindex.
- `/dashboard/runs/[id]` (app/dashboard/runs/[id]/) — the report page (T-039, mockup `context/product/design-report-page.html`): a completed run renders masthead (brand line, company h1, domain · NACE label · date meta) + `FindingsStrip` + numbered chapter sections (`ChapterRule` + card): 1 `KpiLedger`, 2 `BenchmarkCard`, 3 `IncidentCostCard`, 4 `ExpertMatchesCard`, 5 `ProposalCard` (2/4/5 only when a benchmark row exists — legacy pre-stage-3 runs keep dim strip entries), closed by the provenance line. Non-completed states render `RunStatusCard` (+ `RunProgress` while queued or in progress). Another user's run is not-found. noindex.
- `/expert/apply` (app/(site)/expert/apply/) — the application page: form for `expert_status = none`, `ExpertStatusCard` for pending/rejected; experts are redirected to `/expert`. noindex.
- `/expert` (app/(site)/expert/page.tsx) — the expert surface (role `expert` only, others → `/expert/apply`): approved card, `ExpertMatchesList`, `ExpertProfileForm` prefilled. `app/(site)/expert/layout.tsx` is the container. noindex.
- `/admin` … `/admin/runs`, `/admin/runs/[id]`, `/admin/users`, `/admin/experts` (app/(site)/admin/) — the admin surface, `requireAdmin()` on every page (non-admins → `/auth/redirect`); `app/(site)/admin/layout.tsx` holds `AdminNav`. noindex.
- `app/not-found.tsx` — the global 404 for unmatched URLs, wrapped in `SiteShell` itself (the fallback renders outside the `(site)` group, so bare content would lose the chrome and landmarks). `app/(site)/not-found.tsx` catches notFound() bubbled from `(site)` pages bare — its layout already brings `SiteShell` and the root file would double it. Dashboard-internal notFound() still uses `app/dashboard/not-found.tsx`. All three render `NotFoundCard`-style copy.
- `/design` (app/(site)/design/page.tsx) — design-system reference: every token pair, lines, chart ramp, radius, type scale, Button variants × sizes. Unlinked; noindex. Update it whenever a token or Button variant changes.
